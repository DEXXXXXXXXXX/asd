# 🎫 Ticket System Pro

نظام تذاكر ديسكورد احترافي ومتكامل — بديل جاهز شبيه بـ **Wicks**، مبني بالكامل على **أوامر سلاش (/)**، بدون الحاجة لتعديل أي ملف يدوياً. كل الإعدادات تتم عبر الأوامر مباشرة داخل ديسكورد.

---

##  المميزات

| # | الميزة | التفاصيل |
|---|--------|----------|
| 1 | نظام تذاكر بـ 5 أقسام | تضيف/تحذف الأقسام بأمر، كل قسم بكاتاقوري وإيموجي خاص به |
| 2 | رسالة ترحيب تلقائية | تُرسل تلقائياً فور فتح كل تذكرة، ونصها قابل للتعديل بأمر |
| 3 | أزرار تفاعلية كاملة | استلام 🙋 / إغلاق 🔒 / إعادة فتح 🔓 / حذف 🗑️ |
| 4 | لوقات كاملة لكل تذكرة | تُرسل لقناة السجلات عند الحذف: من فتحها، من استلمها، من أغلقها، الأوقات، والسبب |
| 5 | عداد تلقائي لأرقام التذاكر | كل تذكرة تأخذ رقماً تسلسلياً فريداً لكل سيرفر |
| 6 | إعدادات كاملة بالأوامر | لا حاجة لأي ملف إعدادات — كل شي (الأقسام، الرتب، قناة اللوق، الرسالة، شكل البانل) يُضبط بأمر سلاش |
| 7 | ترانسكريبت HTML احترافي | نسخة كاملة من كل رسائل التذكرة (بتصميم شبيه بديسكورد) — تُرسل تلقائياً لصاحب التذكرة بالخاص عند الحذف، وزر لعرضها في أي وقت |
| 8 | حماية من تكرار التذاكر | لا يمكن لنفس العضو فتح أكثر من تذكرة مفتوحة بنفس الوقت |
| 9 | إدارة أعضاء التذكرة | إضافة/إزالة أي عضو من التذكرة عبر أمر |
| 10 | أمر حالة البوت | يعرض البينق، مدة التشغيل، وعدد السيرفرات |

## ⚙️ المتطلبات

- Node.js إصدار **18** أو أحدث
- بوت مُنشأ من [Discord Developer Portal](https://discord.com/developers/applications) مع تفعيل:
  - `Server Members Intent`
  - `Message Content Intent`

---

## 🚀 التثبيت والتشغيل

```bash
# 1) تثبيت المكتبات
npm install

# 2) انسخ ملف الإعدادات وعبّي التوكن والآيدي
cp .env.example .env
# افتح .env وضع DISCORD_TOKEN و CLIENT_ID (و GUILD_ID اختيارياً للتجربة السريعة)

# 3) سجّل الأوامر على ديسكورد
npm run deploy

# 4) شغّل البوت
npm start
```

> 💡 إذا وضعت `GUILD_ID` في `.env` فستظهر الأوامر فوراً في ذلك السيرفر فقط (مثالي للتجربة). اتركه فارغاً لتسجيل الأوامر بشكل عام على كل سيرفراتك (قد يستغرق حتى ساعة للظهور).

## 🧭 خطوات الإعداد داخل ديسكورد (بالترتيب)

1. `/ticket-setup` — تهيئة النظام لأول مرة في السيرفر
2. `/ticket-department add name:الدعم الفني emoji:🛠️ category:#كاتاقوري-التذاكر` — كرر حتى 5 مرات لإضافة كل الأقسام
3. `/ticket-role add role:@الدعم` — أضف رتبة أو أكثر تقدر تدير التذاكر (استلام/إغلاق/حذف)
4. `/ticket-logchannel channel:#ticket-logs` — قناة استقبال سجلات وترانسكريبت التذاكر المغلقة
5. `/ticket-welcome message:نص رسالة الترحيب` — (اختياري) تخصيص رسالة الترحيب
6. `/ticket-panel edit title:... description:... color:#2b2d31` — (اختياري) تخصيص شكل البانل
7. `/ticket-panel send channel:#فتح-تذكرة` — إرسال البانل النهائي للأعضاء

## 🔘 الأزرار داخل التذكرة

**أثناء الفتح:** استلام 🙋 (للمشرفين فقط) — إغلاق 🔒 (لصاحب التذكرة أو مشرف)
**بعد الإغلاق:** إعادة فتح 🔓 — حذف 🗑️ — عرض الترانسكريبت 📄 (كلها للمشرفين)

عند الضغط على "إغلاق" تظهر نافذة (Modal) لكتابة سبب الإغلاق (اختياري).

---

## 📄 كيف يعمل الترانسكريبت

عند الضغط على **حذف**:
1. يقوم البوت بجلب كامل رسائل التذكرة (نصوص، إيمبيدات، مرفقات) وتحويلها لملف **HTML** بتصميم داكن شبيه بديسكورد.
2. يُرسل الملف مع ملخص إحصائي (من فتحها، من استلمها، الأوقات، السبب) إلى **قناة السجلات**.
3. يُرسل نفس الملف **رسالة خاصة لصاحب التذكرة** — يفتحه في أي متصفح ليشاهد كل ما جرى بالتذكرة.
4. تُحذف القناة تلقائياً بعد إرسال الملفات.

كما يمكن لأي مشرف الضغط على زر "عرض الترانسكريبت" في أي وقت (حتى قبل الحذف) للحصول على نسخة فورية.

> ℹ️ الملف يُرسل كمرفق (Attachment) مباشر — لا حاجة لاستضافة سيرفر ويب خارجي. إذا رغبت لاحقاً باستضافة الترانسكريبتات على رابط ويب دائم، يمكن تطوير ذلك بإضافة سيرفر Express بسيط يخزن الملفات ويعرضها برابط — أخبرني إذا احتجت هذا التوسع.

## 🗂️ هيكلة المشروع

```
ticket-system-pro/
├── src/
│   ├── index.js              # نقطة تشغيل البوت
│   ├── deploy-commands.js    # تسجيل أوامر السلاش
│   ├── commands/              # كل أوامر السلاش
│   ├── events/                 # ready + interactionCreate
│   ├── handlers/               # منطق إنشاء/استلام/إغلاق/حذف/ترانسكريبت التذاكر
│   └── utils/                  # تخزين، إعدادات، إيمبيدات، أزرار، مولّد الترانسكريبت
├── data/
│   ├── config/<guildId>.json  # إعدادات كل سيرفر (تُنشأ تلقائياً)
│   └── tickets/<guildId>.json # بيانات التذاكر الحالية (تُنشأ تلقائياً)
├── package.json
└── .env.example
```

> 📌 التخزين يتم بملفات JSON بسيطة لكل سيرفر — مناسب تماماً للسيرفرات الصغيرة والمتوسطة. لسيرفر كبير جداً بآلاف التذاكر يومياً يُفضّل الترقية لقاعدة بيانات مثل SQLite أو MongoDB (يمكن تطوير ذلك عند الحاجة).
